RRecap — what to remember

  • Three places agents add value: task automation, data analytics, decision-making.
  • Data grounding requires accuracy, relevance, timeliness, cleanliness, availability.
  • Organize business data so it's available for other AI systems — single source of truth wherever possible.
  • Architects audit the data BEFORE designing the agent, not after.
  • Use Microsoft Purview, Dataverse, Microsoft Fabric, and SharePoint Premium to manage grounding data.

KKey concepts

Task automation
Agents handling repeatable, structured work end-to-end (invoice reconciliation, ticket routing).
Data analytics agent
Agents producing summaries, trends, and decisions from data — not doing the underlying transactions.
Decision-making agent
Agents that recommend or take judgment calls, often with human-in-the-loop for high-stakes calls.
Grounding
Connecting an LLM to authoritative data so its answers cite that data instead of hallucinating.
Data readiness (5)
Accuracy · Relevance · Timeliness · Cleanliness · Availability — the architect's pre-build checklist.
Dataverse
Microsoft's structured business-data platform; first-class grounding source for Copilot Studio.
Microsoft Fabric
Unified analytics + lakehouse platform; common grounding source for enterprise AI workloads.

CCheat sheet — when…then

When grounding data is stale → call it out; timeliness fails the readiness check.
When a system has no API → consider Computer Use later, but prefer a connector first.
When multiple AI systems will use the same data → centralize in SharePoint / Dataverse / Fabric with metadata.
When stakeholders want to skip governance → say no, then explain risk and rework.
When deterministic + audited output is non-negotiable → don't use generative AI.
