RRecap — what to remember

  • Microsoft's Responsible AI standard: fairness, reliability/safety, privacy/security, inclusiveness, transparency, accountability.
  • Agent security covers identity, authorization, secret management, network isolation, content safety.
  • Governance: who can build what, where, with which models, on which data.
  • Vulnerabilities include prompt injection, jailbreaks, training-data poisoning, model exfiltration.
  • Validate data residency and movement compliance in every region.
  • Design audit trails for changes to models, prompts, and grounding data.

KKey concepts

Microsoft Responsible AI principles (6)
Fairness · Reliability and safety · Privacy and security · Inclusiveness · Transparency · Accountability.
Prompt injection
Adversarial content embedded in tool data or input that manipulates the agent into ignoring instructions or leaking data.
Defense in depth
Layered defenses: input filtering · content safety · output validation · least-privilege tools · monitoring.
Data residency
Compliance constraint that data must remain in specified geographies; design Azure regions and flows accordingly.
Microsoft Purview
Unified governance, classification, and DLP that controls what Copilot can see, share, and retain.
Audit trail
Who changed what, when, why — for prompts, models, configurations, grounding data.
Identity passthrough / security trimming
Agent only sees what the requesting user is allowed to see; the M365 Copilot pattern.

CCheat sheet — when…then

When designing security → apply defense in depth, never rely on one control.
When data residency matters → choose Azure regions, validate flows, document for audit.
When governing Copilot → Purview is your control plane.
When grounding agents → implement identity passthrough and security trimming.
When changes happen → log who/what/when/why for every prompt and model change.
When prompt injection is the threat → add input filtering, content safety, output validation, least-privilege.
