RRecap — what to remember

  • Three agent personas: task agents, autonomous agents, prompt-and-response agents.
  • Copilot Studio is the design surface for low/no-code agents and topics.
  • Topics + fallback + generative orchestration combine to handle real-world conversations.
  • Connectors integrate Dynamics 365 Sales, Contact Center channels, and external data.
  • Apply the Power Platform Well-Architected Framework to AI workloads.
  • Choose between standard NLP, Azure CLU, and generative orchestration for each scenario.

KKey concepts

Task agent
Bounded, repeatable agent that does a specific job inside a human-driven flow.
Autonomous agent
Goal-pursuing agent that runs end-to-end across multiple steps without per-step human prompting.
Prompt-and-response agent
Single-turn agent that answers a question from a knowledge source.
Topic + fallback
Copilot Studio building blocks: topics handle known intents; fallback handles the rest, often via generative answers.
Generative orchestration
Copilot Studio mode where the model dynamically picks topics/tools — best for open, multi-step conversations.
Power Platform Well-Architected Framework
Reliability · Security · Performance Efficiency · Operational Excellence · Experience Optimization for intelligent workloads.
Foundry Tools
Pre-built building blocks for agent design — knowledge, evaluation, code interpreter, function calling.

CCheat sheet — when…then

When intents are highly structured → use standard NLP / topics, not generative orchestration.
When conversations are open-ended and multi-step → use generative orchestration.
When the agent must work the phone → design for Dynamics 365 Contact Center voice channel.
When designing Copilot for D365 Sales → configure business terms, customizations, connectors.
When agent flow logic gets complex → use named agent flows with triggers, AI prompts, and connectors.
