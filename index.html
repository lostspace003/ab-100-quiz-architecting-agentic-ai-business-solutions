Module 1 of 11

Introduction to Agentic AI Business Solution Architecture

The architect is the bridge between business strategy and AI delivery.

0 of 8 answered Score: 0/8 0%

Quiz complete

RRecap — what to remember

  • AI architects align AI with business goals, not the other way around.
  • Their core duties: vision, data readiness, integration, responsible AI, KPIs, alignment.
  • AI transformation is a five-phase loop: define goals → strategy → architecture → implement → monitor and optimize.
  • Best practices: start with measurable outcomes, modular design, responsible AI, collaboration, leverage Azure AI services.
  • Microsoft AI surfaces: Microsoft 365 Copilot, Copilot Studio, Microsoft Foundry (and Foundry Tools), Dynamics 365 Copilots, Power Platform AI.
  • Out-of-the-box agents exist across Microsoft 365 and Dynamics 365 — extend before you build.

KKey concepts

AI architect
Translates business strategy into a scalable, secure, responsibly-governed AI design that developers can implement.
Agentic AI
AI systems that pursue goals across multiple steps with tools and decisions, not just one-turn responses.
Microsoft 365 Copilot
Microsoft's productivity Copilot embedded in Word, Excel, Outlook, Teams, and PowerPoint.
Copilot Studio
Low-code surface to build and customize agents and topics for business users.
Microsoft Foundry
Pro-dev platform for custom models, agents, evaluation, and agent tooling.
Out-of-the-Box (OOB) agent
An agent or Copilot Microsoft already ships, configurable rather than built from scratch.
Responsible AI
Microsoft's six-principle standard for fairness, reliability/safety, privacy/security, inclusiveness, transparency, accountability.
AI Center of Excellence
A cross-functional team that owns strategy, governance, platform, prompt engineering, RAI, and enablement for an organization's AI.

CCheat sheet — when…then

When a customer says 'we want AI' → first ask: what business outcome are we measuring?
When the data is scattered across systems → assess data readiness BEFORE designing the agent.
When users live in M365 → start with Microsoft 365 Copilot, extend before building.
When the request is bounded and configurable → prefer an OOB agent; build only the gap.
When governance is skipped → push back; it is requirements, not an afterthought.

Analyze requirements for AI-powered business solutions

Requirements + data quality determine whether the AI project can ever work.

0 of 8 answered Score: 0/8 0%

Quiz complete

RRecap — what to remember

  • Three places agents add value: task automation, data analytics, decision-making.
  • Data grounding requires accuracy, relevance, timeliness, cleanliness, availability.
  • Organize business data so it's available for other AI systems — single source of truth wherever possible.
  • Architects audit the data BEFORE designing the agent, not after.
  • Use Microsoft Purview, Dataverse, Microsoft Fabric, and SharePoint Premium to manage grounding data.

KKey concepts

Task automation
Agents handling repeatable, structured work end-to-end (invoice reconciliation, ticket routing).
Data analytics agent
Agents producing summaries, trends, and decisions from data — not doing the underlying transactions.
Decision-making agent
Agents that recommend or take judgment calls, often with human-in-the-loop for high-stakes calls.
Grounding
Connecting an LLM to authoritative data so its answers cite that data instead of hallucinating.
Data readiness (5)
Accuracy · Relevance · Timeliness · Cleanliness · Availability — the architect's pre-build checklist.
Dataverse
Microsoft's structured business-data platform; first-class grounding source for Copilot Studio.
Microsoft Fabric
Unified analytics + lakehouse platform; common grounding source for enterprise AI workloads.

CCheat sheet — when…then

When grounding data is stale → call it out; timeliness fails the readiness check.
When a system has no API → consider Computer Use later, but prefer a connector first.
When multiple AI systems will use the same data → centralize in SharePoint / Dataverse / Fabric with metadata.
When stakeholders want to skip governance → say no, then explain risk and rework.
When deterministic + audited output is non-negotiable → don't use generative AI.

Module 3 of 11

Design overall AI strategy for business solutions

The biggest module — set the strategy that the rest of the course decorates with detail.

0 of 8 answered Score: 0/8 0%

Quiz complete

RRecap — what to remember

  • Use the Microsoft Cloud Adoption Framework AI scenarios as your skeleton.
  • Design for multi-agent first; M365 Copilot, Copilot Studio, and Foundry interoperate.
  • Leverage prebuilt agents before building custom; document use cases for each.
  • Custom build vs extend M365 Copilot vs build Foundry agent — driven by scope, audience, and IP needs.
  • Prompt libraries, prompt-engineering guidelines, and a Microsoft AI Center of Excellence anchor scaling.
  • Multi-Dynamics 365 strategies coordinate AI across CX, service, finance, supply chain.

KKey concepts

Cloud Adoption Framework — AI scenarios
Microsoft's prescriptive AI playbook: Strategy → Plan → Ready → Adopt → Govern → Manage.
Multi-agent solution
Architecture where specialized agents (task, autonomous, prompt-and-response) interoperate to deliver an outcome.
Prompt library
Curated, governed, version-controlled set of reusable prompts and templates.
Small Language Model (SLM)
Compact model tuned for narrow, latency-sensitive tasks; cheaper-per-call than frontier models.
RAG (Retrieval-Augmented Generation)
Pattern where a model retrieves relevant data at query time and grounds its answer on it.
Custom build / extend / buy
The architect's three-way decision driven by IP value, time-to-value, and platform fit.
AI Center of Excellence (CoE)
Six disciplines: strategy, governance, platform, prompt engineering, RAI, enablement.

CCheat sheet — when…then

When the customer has Microsoft 365 → extend M365 Copilot before building Foundry agents.
When users live in Dynamics 365 → activate the prebuilt Copilots, then extend at the seams.
When latency or cost dominates → propose an SLM with a model router escalation path.
When IP differentiation is the reason → only then build custom in Foundry.
When prompts are scaling → introduce a governed prompt library, not a wiki.

Evaluate the costs and benefits of an AI-powered business solution

If you can't defend the business case, the project never ships.

0 of 8 answered Score: 0/8 0%

Quiz complete

RRecap — what to remember

  • ROI = (benefits − costs) / costs, but use ranges and time-to-value, not point estimates.
  • TCO covers licenses, tokens/inference, integration, change management, monitoring, ongoing tuning.
  • Build vs. buy vs. extend is decided by IP value, time-to-market, and platform fit.
  • Model routers send each request to the cheapest model that meets quality bar.
  • Track soft ROI: time saved, deflection, CSAT, error reduction — not only hard dollars.

KKey concepts

ROI
(Benefits − Costs) / Costs. Use ranges and time-to-value, not point estimates.
TCO
Total cost of ownership — licenses, tokens/inference, integration, change management, monitoring, tuning.
Build vs. Buy vs. Extend
Decision driven by IP value, time-to-market, platform fit, and TCO. Extend wins most often.
Model router
Routes each request to the cheapest model that meets the quality bar — cost-aware pattern.
Soft ROI
Time saved, deflection, CSAT, error reduction — convert to dollars via loaded cost-per-hour × volume.
Payback period
Time to recover total cost; defended via low/base/high scenarios with documented assumptions.

CCheat sheet — when…then

When CFO asks for ROI → present 3 scenarios (low / base / high) with assumptions.
When tokens are the cost concern → propose SLM + router; reserve frontier for hard queries.
When TCO line items are missing → add monitoring, tuning, and change management explicitly.
When build/buy/extend is unclear → score each on IP, time-to-value, and platform fit.
When benefits feel soft → quantify with AHT × volume × loaded cost.

Design AI and agents for business solutions

Heaviest design module. Designing the agents themselves — Copilot, Foundry agents, agent flows.

0 of 8 answered Score: 0/8 0%

Quiz complete

RRecap — what to remember

  • Three agent personas: task agents, autonomous agents, prompt-and-response agents.
  • Copilot Studio is the design surface for low/no-code agents and topics.
  • Topics + fallback + generative orchestration combine to handle real-world conversations.
  • Connectors integrate Dynamics 365 Sales, Contact Center channels, and external data.
  • Apply the Power Platform Well-Architected Framework to AI workloads.
  • Choose between standard NLP, Azure CLU, and generative orchestration for each scenario.

KKey concepts

Task agent
Bounded, repeatable agent that does a specific job inside a human-driven flow.
Autonomous agent
Goal-pursuing agent that runs end-to-end across multiple steps without per-step human prompting.
Prompt-and-response agent
Single-turn agent that answers a question from a knowledge source.
Topic + fallback
Copilot Studio building blocks: topics handle known intents; fallback handles the rest, often via generative answers.
Generative orchestration
Copilot Studio mode where the model dynamically picks topics/tools — best for open, multi-step conversations.
Power Platform Well-Architected Framework
Reliability · Security · Performance Efficiency · Operational Excellence · Experience Optimization for intelligent workloads.
Foundry Tools
Pre-built building blocks for agent design — knowledge, evaluation, code interpreter, function calling.

CCheat sheet — when…then

When intents are highly structured → use standard NLP / topics, not generative orchestration.
When conversations are open-ended and multi-step → use generative orchestration.
When the agent must work the phone → design for Dynamics 365 Contact Center voice channel.
When designing Copilot for D365 Sales → configure business terms, customizations, connectors.
When agent flow logic gets complex → use named agent flows with triggers, AI prompts, and connectors.

Design extensibility of AI solutions

Stretch the platform — when out-of-the-box isn't enough.

0 of 8 answered Score: 0/8 0%

Quiz complete

RRecap — what to remember

  • Foundry custom models, M365 Copilot agents, and Copilot Studio extensibility are the three big extension surfaces.
  • MCP (Model Context Protocol) lets agents pull tools and data through a standard interface.
  • Computer Use in Copilot Studio automates apps and websites that have no API.
  • Reasoning + voice mode in Copilot Studio shape complex agent behavior.
  • Microsoft 365 surfaces — Teams, SharePoint — are first-class deployment targets for agents.

KKey concepts

Custom Foundry model
Trained or tuned in Microsoft Foundry when proprietary data, latency, or IP isolation justify custom.
MCP (Model Context Protocol)
Open standard letting agents discover and call external tools and data through a consistent interface.
A2A (Agent-to-Agent)
Protocol for agents to delegate to each other across systems.
Computer Use
Capability to drive a UI when no API exists — for legacy / third-party apps.
Reasoning + voice mode
Copilot Studio behaviors that let the agent decompose goals dynamically and operate as voice.
M365 Copilot extensibility
Surfacing custom agents and skills inside Word, Excel, Outlook, Teams, SharePoint.

CCheat sheet — when…then

When an API exists → use it; reserve Computer Use for legacy systems.
When proprietary data + IP + latency align → build a custom model in Foundry.
When agents need tools that change → wire them via MCP, not bespoke connectors.
When users live in Teams → publish the agent into Teams, don't build a separate site.
When agents must coordinate → use A2A for delegation, MCP for shared tooling.

KKey concepts

Telemetry

Containment rate

% of issues resolved on first interaction — better quality signal than containment alone.
Knowledge drift
When source content changes but grounding wasn't refreshed; common cause of post-launch quality drop.
Average Handle Time (AHT)
Service KPI; AHT × volume × loaded cost-per-agent converts to defensible dollar savings.
Tuning loop
Telemetry → identify gap → adjust knowledge / prompts / topics → re-evaluate. Hours, not weeks.

CCheat sheet — when…then

When tuning is needed fast → adjust knowledge / prompts / topics, not the model.
When risk is high → benchmark escalation rate against the task's risk tier.
