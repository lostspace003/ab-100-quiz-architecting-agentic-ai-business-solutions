Agents and prompts are production assets — they need ALM like any other workload.

RRecap — what to remember

  • ALM applies to data, prompts, topics, custom models, and configurations.
  • Solutions in Power Platform / Dataverse are the unit of deployment for Copilot Studio agents.
  • Foundry agents have their own ALM with environments and pipelines.
  • Dynamics 365 ALM extends to Copilot configuration in finance, supply chain, customer experience, and service.
  • Source control + environments (dev / test / prod) + gated promotion + rollback are non-negotiable.

KKey concepts

Solution (Power Platform)
The unit of deployment for Copilot Studio agents across dev / test / prod.
Environment
Isolated runtime — dev / test / prod — gated promotion is non-negotiable.
ALM for prompts
Versioned, peer-reviewed, gated promotion. Prompts are code.
ALM for data
Schema versions, lineage, refresh cadence, PII handling — its own lifecycle, not the agent's.
Configuration migration
Supported tools to package and move D365 Copilot configuration across environments.
Model artifact bundle
Weights · training-data manifest · evaluation set · hyperparameters · prompt templates · deployment config — versioned together.

CCheat sheet — when…then

When deploying a Copilot Studio agent → solution → dev → test → prod, with rollback.
When prompts change → require peer review and version control, not chat-based edits.
When data schema changes → update lineage and refresh grounding pipelines.
When models retrain → re-version the entire bundle, not just weights.
When prod breaks → rollback to the previous solution version from a controlled artifact store.
