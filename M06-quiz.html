RRecap — what to remember

  • Foundry custom models, M365 Copilot agents, and Copilot Studio extensibility are the three big extension surfaces.
  • MCP (Model Context Protocol) lets agents pull tools and data through a standard interface.
  • Computer Use in Copilot Studio automates apps and websites that have no API.
  • Reasoning + voice mode in Copilot Studio shape complex agent behavior.
  • Microsoft 365 surfaces — Teams, SharePoint — are first-class deployment targets for agents.

KKey concepts

Custom Foundry model
Trained or tuned in Microsoft Foundry when proprietary data, latency, or IP isolation justify custom.
MCP (Model Context Protocol)
Open standard letting agents discover and call external tools and data through a consistent interface.
A2A (Agent-to-Agent)
Protocol for agents to delegate to each other across systems.
Computer Use
Capability to drive a UI when no API exists — for legacy / third-party apps.
Reasoning + voice mode
Copilot Studio behaviors that let the agent decompose goals dynamically and operate as voice.
M365 Copilot extensibility
Surfacing custom agents and skills inside Word, Excel, Outlook, Teams, SharePoint.

CCheat sheet — when…then

When an API exists → use it; reserve Computer Use for legacy systems.
When proprietary data + IP + latency align → build a custom model in Foundry.
When agents need tools that change → wire them via MCP, not bespoke connectors.
When users live in Teams → publish the agent into Teams, don't build a separate site.
When agents must coordinate → use A2A for delegation, MCP for shared tooling.
